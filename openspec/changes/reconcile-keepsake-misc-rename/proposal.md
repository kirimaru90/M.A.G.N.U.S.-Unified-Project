## Why

The archived change `misc-items-catalog` renamed the character inventory collection `other → misc` end-to-end in the API and pip-boy code (and the API now rejects an `other` inventory body with HTTP 400). Two artifacts that reference that collection were outside that change's delta set and were left describing the old `other` key:

- `pipboy-character-creation`'s spec still says the creation-wizard **keepsake** is written to `inventory.other`. The shipped pip-boy code already writes `inventory.misc` (a passing Playwright test asserts it), so the spec now contradicts both the code and `api-character-inventory`.
- The committed API contract `apps/packages/api-spec/openapi.json` still exposes `other` on the inventory DTOs.

This change is a documentation/artifact catch-up: it aligns the stale spec text and the committed contract with behaviour that already ships. No runtime behaviour changes.

## What Changes

- Update the `pipboy-character-creation` spec so the keepsake is described as landing in `inventory.misc` (the renamed successor of `other`), matching `api-character-inventory` and the pip-boy code. Three references change: the instantiation step and the two keepsake scenarios.
- Regenerate and commit `apps/packages/api-spec/openapi.json` so `UpdateInventoryDto` / `PatchInventoryDto` expose `misc` instead of `other`. This file is auto-generated by NestJS Swagger on API startup (`apps/api/api/src/main.ts`), so regeneration — not hand-editing — is the fix; the committed copy is simply stale.
- No application source change: `apps/pip-boy/src/screens/create.js` already writes `inventory.misc`, and the character-creation Playwright suite already asserts it.

- **Risk:** negligible; this reconciles documentation with already-verified behaviour.
