## Why

The authoring guide (§5.2) is the canonical reference for content authors, but the engine, specs, and docs diverge in several ways discovered during a spec-compliance audit:

1. **Variant field name mismatch**: the variant selector is `condition` in `node-resolver.js` and the spec, but `when` in both reference docs.
2. **Condition grammar mismatch**: both reference docs describe a `{ "key": "...", "eq": value }` inline-operator format; the evaluator (`conditions.js`) parses `{ "var": "...", "op": "...", "value": ... }`. Any content following the docs silently produces wrong results.
3. **`not` combinator undocumented**: `conditions.js` and the spec support `not`; neither reference doc mentions it.
4. **Per-variant `components` silently ignored**: the authoring guide implies variants can carry `components`, but the resolver always returns `node.components`.
5. **Choice `when` never evaluated**: the authoring guide (§5.3) says a choice is hidden when its `when` is false; `showChoices()` renders all choices unconditionally.
6. **Reference docs unversioned**: no version or date tracking on either doc in `reference/`.

All six issues are fixed in this change. The condition grammar decision: since content is generated by AI agents or dedicated interfaces (not typed by hand), the `var/op/value` format is the right canonical form — it is regular, JSON-Schema-validatable, and maps cleanly to the evaluator's `switch (condition.op)`. Both reference docs are updated to match the implementation (not the other way around).

## What Changes

- **`node-resolver.js`**: read `variant.when` instead of `variant.condition`; use `variant.components ?? node.components`.
- **`terminal.js` `showChoices()`**: filter each choice by evaluating `choice.when` against the current snapshot; hide choices that evaluate to false.
- **`reference/terminal-authoring-guide.md`**: §6 condition syntax updated to `var/op/value`; `not` combinator added; version header added (v1.1 · 2026-05-22).
- **`reference/robco-terminal-architecture.md`**: condition syntax section updated to `var/op/value`; `not` combinator added; version header added (v1.1 · 2026-05-22).
- **`openspec/specs/conditional-variants/spec.md`**: field names updated to `when`; condition grammar updated to `var/op/value` throughout; `not` combinator scenarios added; per-variant `components` requirement and scenarios added.
- **`openspec/specs/input-components/spec.md`**: clarify that `components` resolution follows the variant-override model.

## Version header format

Both reference docs gain a YAML frontmatter block at the very top:

```yaml
---
version: 1.1
date: 2026-05-22
---
```

Subsequent changes that modify either doc bump the minor version and update the date.

## Capabilities

### New Capabilities
- `per-variant-components`: Variants can declare their own `components` array; the resolver uses it in place of `node.components`.
- `choice-visibility-conditions`: Choices with a `when` field are hidden from the rendered list when the condition evaluates to false against the current snapshot.

### Modified Capabilities
- `conditional-variants`: Variant selector field renamed from `condition` to `when`; condition grammar canonically `var/op/value`; `not` combinator added to spec and docs; per-variant `components` override semantics added.
- `input-components`: `components` field on a variant takes precedence over the node-level `components`.

## Impact

- `src/engine/node-resolver.js`: two-line change — `variant.when` + `variant.components ?? node.components`.
- `src/screens/terminal.js`: `showChoices()` filters choices through `evaluate(choice.when, getSnapshot())` when `when` is present.
- `openspec/specs/conditional-variants/spec.md`: field names, grammar, `not` scenarios, `components` scenarios.
- `openspec/specs/input-components/spec.md`: one clarifying requirement.
- `reference/terminal-authoring-guide.md`: version header + §6 grammar update + `not` addition.
- `reference/robco-terminal-architecture.md`: version header + condition syntax section update + `not` addition.
- Existing holotape JSON using `condition` on variants must migrate to `when`. Content using inline-op grammar (`{ "key": ..., "eq": ... }`) must migrate to `var/op/value`. (Content migration only — no API or schema changes.)
